## Delegation

### Delegate heavy work (`delegate-heavy-work`)

**Rule.** Delegate substantial work to sub-agents. The parent agent orchestrates, verifies the results, and commits.

**Why.** Keeps the parent's context small and lets independent work run in parallel.

Tags: delegation, cost

## Version control

### Commit only your own paths (`commit-own-paths`)

**Rule.** Commit only the paths you changed. Branch off the default branch rather than committing to it, and commit or push only when asked.

**Why.** Avoids sweeping in concurrent or unrelated changes.

Tags: vcs

## Safety and human control

### No unrequested external writes (`no-unrequested-external-writes`)

**Rule.** Never write to an external system (push to a remote, send a message, mutate a service) unless explicitly asked. Preparing a draft is fine.

**Why.** External writes are hard or impossible to reverse.

Tags: safety, vcs

### Gate irreversible actions (`gate-irreversible-actions`)

**Rule.** Ask a human only about decisions that are irreversible, reach outside, or will run unattended. Ask one question at a time.

**Why.** Respects the human's attention and keeps control where it matters.

Tags: safety, communication

### Humans execute risky steps (`human-executes-risky-steps`)

**Rule.** State who executes every action. Sending, approving, and irreversible steps belong to the human.

**Why.** Removes ambiguity about what is automated and what is manual.

Tags: safety, communication

## Deliverables

### Deliverables show the current state (`deliverables-current-state`)

**Rule.** A deliverable states the current conclusion only: no strikethrough and no change-log prose. Structure it as conclusion, then evidence, then detail, and prefer diagrams.

**Why.** Readers should not have to reconstruct history to find the answer.

Tags: deliverables

## Communication

### Preflight before deep work (`preflight-before-deep-work`)

**Rule.** Verify every input and access route you need before starting deep work. Never fill a gap by guessing; surface what is missing.

**Why.** Avoids building on wrong assumptions.

Tags: communication, safety

### Announce and report long work (`announce-and-report-long-work`)

**Rule.** Announce work that will take minutes before starting it, and report progress on a regular cadence.

**Why.** The human should never be left waiting blind.

Tags: communication

### Show full paths (`show-full-paths`)

**Rule.** Refer to outputs by full, unambiguous paths.

**Why.** Shortened paths get resolved against the wrong base.

Tags: communication

## Cost and hygiene

### Conversation cost discipline (`conversation-cost-discipline`)

**Rule.** Do not re-read what you already have, do not dump large outputs, and offload large reads and writes.

**Why.** Every turn re-reads the whole context, so waste compounds.

Tags: cost

### Prefer a clean state (`prefer-clean-state`)

**Rule.** Prefer the correct, clean state over a workaround. Fix known-bad leftovers, and refine details in operation.

**Why.** Technical debt compounds.

Tags: cost, deliverables
